LLM Gateway — описание компонентов (L3)

LLM Gateway — единственная точка, через которую Backend обращается к LLM Provider. На входе он отвечает за то, чтобы наружу не ушли персональные данные абонента; на выходе — за то, чтобы к абоненту не пришёл небезопасный или недостоверный (галлюцинация) ответ. Между этими двумя проверками находится готовое ядро (LiteLLM Core), которое просто маршрутизирует и стримит.

КомпонентТехнологияРоль в потокеЧто делает
PII Sanitizer Presidio + custom recognizers Вход, sync Принимает промпт от Backend и скрывает ПДн (ФИО, СНИЛС, ИНН, лицевой счёт, телефон, email) до того, как запрос уйдёт к LLM Provider. В лог пишется только pii_report, сырые ПДн — никогда.
Guardrails regex + spaCy/Presidio; LLM-judge (целевое) Выход, sync + async Проверяет ответ модели перед тем, как он попадёт к абоненту. Sync-проверка обрывает поток и возвращает safe fallback: ПДн в выводе — тем же обезличивателем (spaCy NER через Presidio), токсичность / policy / разглашение промпта — regex (LLM не в бюджет 50 мс, тонкие случаи → судья). Async groundedness на выходе шлюза — дешёвая эвристика (доля слов ответа в контексте, provisional). Настоящую оценку (faithfulness, answer relevancy) делает судья (app/quality/judge.py) — отдельная модель, ночным прогоном scripts/run_quality_eval.py по эталонному набору, вне пути абонента.
Quota Manager slowapi + Redis Вход, sync RPS- и месячные квоты на абонента и сессию + глобальный лимит на сервис; источник счётчиков — Redis. При превышении — 429 + Retry-After (RFC 7807).
LiteLLM Core готовое ядро; маршрутизатор в процессе Центр OpenAI-совместимый вызов, маршрутизация моделей по litellm_config.yaml и fallback, retry / circuit breaker / timeout, адаптеры провайдеров, SSE-стриминг. Отдельного прокси-процесса нет: litellm.Router живёт внутри процесса шлюза.

Billing Callback — не выделен. Это не компонент, а две записи метрик из LlmGateway: llm_gateway_tokens_total, llm_provider_used_total и гистограммы времён — в Prometheus (порт 9100, дашборд); плюс одна строка на вызов в таблице usage_events базы Postgres (отдельная база telemetry). Стоимость в деньгах не считается: у проекта нет тарифов провайдера. Роль «аналитика по абонентам / типам / моделям» закрывает usage_events, чего счётчики Prometheus без взрыва кардинальности не дают.
