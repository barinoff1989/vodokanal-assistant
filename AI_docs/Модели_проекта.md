# Модели проекта

**Пять независимых ролей.** Смена модели в одной роли не трогает остальные — это и есть довод
ADR-002 в пользу единого шлюза (LiteLLM): переключение провайдера — правка `LLM_PROVIDER` /
`app/gateway/litellm_config.yaml`, а не код.

**Три контура:** прототип (машина разработки, CPU, закрытая сеть без доступа к GigaChat) →
MVP (Kubernetes в контуре водоканала, GPU-пул под эмбеддинги/реранкер) → тираж (self-hosted
генерация, разворачивается по факту одного из четырёх триггеров ADR-002, не по расписанию).

Везде, где столбец «Этап» не указан отдельно — роль относится к Этапу 1 (вопрос-ответ, без
записи). Этап 2 (запись после подтверждения) модели не использует нигде, кроме одного открытого
пробела — см. последнюю строку.

| Роль | Контур | Модель | Этап | Почему именно эта модель |
|---|---|---|---|---|
| **Отвечающая модель** (генерация ответа абоненту) | Прототип | YandexGPT (`gpt://.../yandexgpt/latest`) | 1 | GigaChat недоступен на машине прототипа: требует корневых сертификатов НУЦ Минцифры |
| | MVP | GigaChat Pro | 1 | Управляемый API на территории РФ — 152-ФЗ соблюдён по построению (ADR-002), не обезличиванием постфактум |
| | Тираж | Qwen2.5-32B INT4 (vLLM, 1× A100 80GB) | 1 | Единственная из рассмотренных конфигураций укладывается и в VRAM (~34 ГБ при 15 конкурентных запросах), и в DoD по латентности: ~125 ток/с против ~19–20 у T4/L4 (150 токенов заняли бы ~7,5 с при бюджете <3 с, раздел 39.1) |
| **Резервный провайдер** (автопереключение при сбое основного, ADR-002 «Подтверждение» п.1) | Прототип | local-test — Qwen2.5-7B-instruct-q4_K_M (Ollama) | 1 | Второй провайдер нужен для теста failover без второго платного контракта; локальная модель уже поднята для офлайн-проверок |
| | MVP | YandexGPT | 1 | Второй управляемый API того же класса — не self-hosted-кандидат ради него самого, а рабочий резерв |
| **Эмбеддинги** (поиск по базе знаний) | Прототип | `intfloat/multilingual-e5-small`, CPU, в процессе Backend | 1 | Замер ADR-014: BGE-M3 — 210 мс при бюджете 100 мс; e5-small — 22 мс, 0,46 ГБ вместо 6,4 ГБ |
| | MVP / Тираж | BGE-M3 (1024-d), GPU (`embedding-inference`, TEI/vLLM) | 1 | ADR-007: качество эмбеддингов приоритетнее задержки при наличии GPU; общий сервис с офлайн ETL (находка F7, окно 02:00–05:00) |
| **Реранкер** (переранжирование `top_k → top_n`) | Прототип | нет — исключён из живого пути | 1 | Кросс-энкодер даёт 5 774 мс на 20 кандидатов при бюджете 100 мс (ADR-014). Офлайн-замер подтвердил пользу (hit@1: 23%→70%), но 20,8 с на вопрос на CPU не годится абоненту |
| | MVP / Тираж | BGE-reranker-v2-m3 (cross-encoder), GPU (`reranker-inference`) | 1 | На GPU задержка приемлема; тот же сервис обслуживает и офлайн-отбор чанков ETL |
| **Запасной классификатор темы** (когда правила `Triage` не нашли тему, v4.55) | Прототип | тот же `multilingual-e5-small` — k-NN по размеченным примерам, не генерация | 1 | Переиспользует уже поднятый эмбеддер поиска (вторая копия весов не грузится, ~22 мс/вызов). Первая редакция (v4.54) звала генеративную модель через Ollama — разброс 0,4–11+ с (Ollama выгружает веса по простою), заменена на близость эмбеддингов |
| **Судья качества ответа** (LLM-as-judge, ADR-007 роль 4a) | Прототип | local-test — Qwen2.5-7B (Ollama) | 1 | ADR-007: судья не должен совпадать с отвечающей моделью (`JudgeConflict` при совпадении); прототип отвечает YandexGPT, судья — другая модель |
| | MVP | YandexGPT | 1 | Отвечает GigaChat Pro — разные провайдеры, конфликта нет |
| | Тираж (опционально) | Llama 3.1, второй self-hosted инстанс | 1 | Нужен только при переходе по триггеру №1 (запрет внешних API): внешний судья (YandexGPT) в этом сценарии сам противоречил бы запрету |
| **PII-обезличивание** (NER на входе запроса и на выходе Guardrails) | Все контуры | spaCy `ru_core_news_md` через Presidio + собственные checksum-распознаватели (СНИЛС/ИНН/лицевой счёт/телефон) | 1 | Не зависит от провайдера генерации — один и тот же обезличиватель на входе и на выходе, во всех контурах без изменений |
| **Классификация темы** (`Topic` — путь ответа) | Все контуры | без модели — regex/ключевые слова (`app/agents/triage.py`) | 1 | Тема решает, звать ли модель вообще; определять её моделью значило бы платить за вызов на каждом запросе, включая те, где модель не нужна (ADR-012, ADR-013) |
| **Агент оркестратора / Form Agent** (сбор недостающих слотов в диалоге) | — | **не выбрана** — открытый пробел | 2 | Этап 2 на заглушках; единственный компонент оркестратора, которому вообще нужна модель (раздел 75.2, 79.2 контекста). На прототипе все обязательные слоты известны из профиля Биллинга — форма не нужна, вызывать нечем |

## Источники

- **ADR-002** (`AI_docs/ADR/ADR-002-llm-hosting-strategy.md`) — стратегия хостинга, четыре триггера перехода на self-hosted, требование двух провайдеров с fallback.
- **ADR-007** (`AI_docs/ADR/ADR-007-mvp-model-composition.md`) — состав моделей MVP (эмбеддинги, реранкер, судья), правило «судья ≠ отвечающая модель», sizing self-hosted тиража.
- **ADR-014** (`AI_docs/ADR/ADR-014-search-models-on-prototype.md`) — почему на прototype не BGE-M3/кросс-энкодер, замер задержки и качества.
- [`app/gateway/litellm_config.yaml`](../app/gateway/litellm_config.yaml) — единственное место, где живут псевдонимы моделей и цепочки fallback по контурам.
- [`app/agents/topic_fallback.py`](../app/agents/topic_fallback.py) — запасной классификатор темы, v4.55.
- `AI_docs/C4_Deployment.html` — self-hosted тираж: GPU-узел, vLLM, sizing-расчёт (раздел 39.1).
- `AI_docs/контекст_4.md`, разделы 75.1, 75.2, 75.6, 79.2 — устройство прототипа как оно есть.

**Не входит в эту таблицу:** судья на живом пути (`app/quality/live.py`) и ночной прогон
(`scripts/run_quality_eval.py`) — это два разных **режима вызова** одной и той же роли «судья»,
не отдельные модели; см. журнал разделы 84, 89.
