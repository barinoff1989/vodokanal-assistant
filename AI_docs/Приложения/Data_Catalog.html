Почему не Feature Store (пока)

Строка 16 (агрегированный профиль абонента) — по сути ровно то, для чего в индустрии существует Feature Store. Но у самой методики есть чёткий критерий применимости, и этот проект ему пока не соответствует:

Одна модельная линияRAG + один LLM-контур, а не «много зрелых моделей в продакшене»
Нет межкомандного переиспользованияпрофиль абонента нужен только этому Backend, не нескольким независимым командам
Latency решается прощекэш/materialized view в Backend закрывает P99<100мс без отдельной платформы

Вывод: строить как обычный кэш сейчас, к вопросу о полноценном Feature Store вернуться, если появится вторая модель/команда, которой нужны те же признаки.
