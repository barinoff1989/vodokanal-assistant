# Пакет ADR для сдачи проекта

Шесть документов ниже — сводка для приёмки, не рабочий журнал разработки. Каждый — 1,5–3 страницы:
вывод, таблица сравнения с альтернативами, ссылка на источник для тех, кто хочет углубиться.

Документы здесь — итоговый результат, а не пересказ процесса разработки.

## Как читать

1. Начать с **ADR-100** — рамка: что вообще сдано и в каких границах.
2. **ADR-200** и **ADR-300** — техническая база решения (стек и модели). ADR-200 включает подробное
   сравнение Python/Go/Node.js для Backend, не только сводную таблицу.
3. **ADR-400** и **ADR-500** — эксплуатационные вопросы (безопасность, ресурсы, деньги на прод).
4. **ADR-600** — что дальше, если проект продолжается.
5. **ТЗ** — отдельная точка входа: бизнес-требования и ограничения без ссылок на конкретные технологии
   и без ссылок на ADR-100…600 — тот документ, который логично было бы получить до того, как появились
   эти решения.

Диаграммы, на которые ссылаются документы, — в `AI_docs/C1/`, `AI_docs/C3/`, `AI_docs/C4_Deployment.html`
(корень `AI_docs/`); статус показан прямо на узлах, по двум осям сразу (см. ADR-100): функциональный
этап («Этап 2» — узлы записи, отложенные до подтверждённого сценария) и контур развёртывания
(«Этап 3» на `C4_Deployment.html` у GPU-пула — обозначение узла тиража, не третий функциональный этап).
