# docs_description — описание документации

Вся документация проекта лежит в папке `AI_docs/` (по схеме сдачи — «/docs»), индекс пакета — `AI_docs/README.md`.
Схемы — HTML-файлы с диаграммами draw.io, открываются в браузере. Ниже описан каждый документ.

## 1. Архитектурные решения (ADD в Markdown) — `AI_docs/ADR/`

Шесть документов; в каждом: статус, решение, таблицы сравнения с альтернативами, источники.

| Файл | О чём | Основные разделы |
|---|---|---|
| `ADR-100-scope-and-limitations.md` | Что сдаётся в прототипе, что отложено на Этап 2 и на контур «тираж» | Две оси стадийности (функциональный этап и контур развёртывания); что сдано; что отложено и почему; целевые компоненты с упрощённой заменой на прототипе; несколько задач в одной реплике; границы, не входящие в сдачу |
| `ADR-200-tech-stack-by-stage.md` | Технологический стек по контурам развёртывания (прототип, MVP, тираж) | Backend и оркестрация (Python/FastAPI, Kubernetes, LangGraph для записи, форма компонента записи); хранилища (Postgres, Redis, Qdrant, телеметрия в Postgres); LLM-хостинг; секреты; наблюдаемость (Zabbix и Grafana владельца, VictoriaLogs для логов, Jaeger по необходимости); сравнение вариантов по каждому слою |
| `ADR-300-model-selection.md` | Выбор моделей по ролям | Классификация (правила, запасной k-NN); эмбеддинги (`multilingual-e5-small`, кандидат BGE-M3); переранжирование (замер кросс-энкодеров на CPU); генерация (YandexGPT, GigaChat Pro, собственная модель как вариант тиража); судья качества |
| `ADR-400-security-by-stage.md` | Безопасность по этапам | Что закрыто сейчас (обезличивание, подтверждение операций, лимиты); что добавляется с Этапом 2, в контуре MVP и тиража; сравнение вариантов по слоям безопасности |
| `ADR-500-resources-and-cost.md` | Ресурсы и стоимость по контурам | Прототип, MVP (8 000 абонентов), тираж (90 000); стоимость токенов в минимальном и максимальном сценариях; объём и нагрузка по контейнерам; расчётный sizing по компонентам; открытые пункты |
| `ADR-600-roadmap-and-migration.md` | План развития | Критерий перехода к MVP (stage-gating Этапа 2); работы перехода прототип → MVP и MVP → тираж с оценками в человеко-днях; общий вывод |

## 4. Приложения и таблицы

| Файл | Содержание |
|---|---|
| `AI_docs/Tech_Stack_Matrix.xlsx` | Матрица «контейнер или связь → технология → альтернативы → проблемы → что на MVP и на тираже → трудозатраты». Листы: «Матрица», «Стоимость», «Источники и допущения», «Объём по контейнерам», «Sizing», «Прогноз стоимости» (расчёт с изменяемыми допущениями) |
| `AI_docs/Capacity_Report.html` | Отчёт о мощности: модель спроса, допущения, стоимость токенов, замеры на машине разработки, sizing |
| `AI_docs/Load_Report.md` | Нагрузочный отчёт: сколько запросов в секунду держит Backend, задержки, загрузка процессора и памяти |
| `AI_docs/Test_List.xlsx` | Список автоматических тестов: сводка, все тесты с описанием, разбивка по файлам |
| `AI_docs/Inquiry_Types.xlsx` | Типы обращений (16 значений справочника и авария) и темы вопросов: ключевые слова, статистика на 136 настоящих обращениях, план работ на MVP |
| `AI_docs/API_Spec.yaml` | Спецификация OpenAPI 3.0.3 (`POST /v1/generate`, `GET /v1/healthz`); собирается из кода скриптом `scripts/build_openapi.py` |
