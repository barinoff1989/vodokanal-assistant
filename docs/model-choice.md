# Выбор локальной тестовой модели

**Шаг 0.5 плана разработки.** Документ существует потому, что план прямо требует зафиксировать выбор
с обоснованием, а не «по аналогии». Это то же правило, из-за которого в проекте однажды появились
недостоверные цифры из постороннего примера (контекст, раздел 26.4).

---

## 1. Какую задачу решает эта модель

Локальная модель **не отвечает абонентам**. На MVP генерацию выполняет управляемый API на территории РФ
(ADR-002). Локальная нужна для трёх вещей:

1. **Отладка промптов** без расхода платных токенов. Расход токенов — единственная статья, растущая
   болезненно при масштабировании (контекст, раздел 42.5), и тратить её на итерации по формулировкам
   промпта неразумно.
2. **Офлайн-проверки Security Layer** — прогон корпуса персональных данных и корпуса атак на промпт
   (шаг 3). Эти прогоны многократны по своей природе.
3. **Нагрузочные профили** (план тестирования, раздел 8). Гонять пять профилей по платному API означало
   бы превратить нагрузочное тестирование в отдельную статью бюджета.

Из этого следует, чего от модели **не требуется**: качества ответов уровня боевого провайдера, точности
на предметной области ЖКХ, прохождения оценки на эталонном наборе. Требуется предсказуемая работа на
процессоре, вменяемый русский язык и совместимость с контрактом шлюза.

---

## 2. Критерии выбора

| Критерий | Почему он |
|---|---|
| Работает на процессоре в разумное время | GPU на машине прототипа нет и не требуется (контекст, раздел 39.2) |
| Помещается в память ноутбука | Пиковый сценарий машины прототипа — 16 ГБ минимум, 32 ГБ комфортно |
| Поддерживает русский язык | Все промпты, база знаний и обращения на русском |
| Разрешительная лицензия | Модель попадёт в проектную документацию и в демонстрацию |
| Есть квантованные сборки | Без квантования 7B на процессоре непрактичен |
| **Родство с моделью тиража** | Ключевой критерий, см. ниже |

**Про родство.** Кандидат на self-hosted-контур тиража — Qwen2.5-32B в INT4 (контекст, раздел 39.1).
Промпты, отлаженные на модели того же семейства, ведут себя ближе к целевой, чем отлаженные на чужой
архитектуре с другим форматом системного сообщения и другой реакцией на инструкции. Это единственный
критерий, который отличает выбор для *этого* проекта от выбора «любая приличная маленькая модель».

## 3. Рассмотренные варианты

| Кандидат | Лицензия | Русский | Родство с тиражом | Вердикт |
|---|---|---|---|---|
| **Qwen2.5-7B-Instruct** | Apache 2.0 | приемлемый для своего размера | **то же семейство, что Qwen2.5-32B** | **выбран** |
| Llama 3.1 8B Instruct | Llama Community License — не свободная, с ограничениями по использованию | слабее на русском | нет | отклонён |
| Mistral 7B Instruct | Apache 2.0 | заметно слабее на русском | нет | отклонён |
| Модели, дообученные на русском (семейство Saiga и аналоги) | зависит от базовой модели | лучше остальных | нет | отклонён |
| Модель меньше 7B (3B и ниже) | разные | хуже следует инструкциям | частично | отклонён |

**Почему отклонены дообученные на русском.** Они дали бы лучший русский, но это не тот критерий, который
здесь решает: модель не отвечает абонентам, ей нужно быть *предсказуемой*, а не хорошей. Взамен пришлось
бы принять зависимость от сопровождения конкретной дообученной сборки и потерять родство с моделью
тиража — то есть проиграть по главному критерию ради второстепенного.

**Почему отклонена Llama 3.1 8B.** Не по качеству, а по лицензии: Llama Community License содержит
ограничения, которых нет у Apache 2.0. Для модели, попадающей в документацию проекта и в демонстрацию,
разрешительная лицензия дешевле в объяснении.

**Почему отклонены модели меньше 7B.** На корпусе атак и на проверках Security Layer важно, чтобы модель
следовала инструкциям системного сообщения — иначе непонятно, что именно проверяет тест: защиту или
неспособность модели удержать инструкцию.

## 4. Решение

**Qwen2.5-7B-Instruct, квантование Q4_K_M, запуск через Ollama.**

| Параметр | Значение |
|---|---|
| Псевдоним в конфигурации шлюза | `local-test` |
| Идентификатор в Ollama | `qwen2.5:7b-instruct-q4_K_M` |
| Идентификатор в LiteLLM | `ollama_chat/qwen2.5:7b-instruct-q4_K_M` |
| Лицензия | Apache 2.0 |

**Почему Q4_K_M, а не более грубое или более точное квантование.** Q4_K_M — распространённый компромисс
между размером и деградацией качества; более грубые варианты заметно теряют в связности при следовании
инструкциям, более точные не дают выигрыша, оправдывающего рост потребления памяти, для задачи, где
качество ответа заведомо не является целью.

**Почему Ollama, а не llama.cpp напрямую.** LiteLLM поддерживает Ollama как провайдера штатно, поэтому
подключение сводится к строке в `litellm_config.yaml`, а не к написанию адаптера. Это прямо соответствует
варианту C из ADR-002: смена способа исполнения модели должна быть операцией конфигурации.

## 5. Замеренные характеристики

**Числа фактические**, получены 2 сентября 2026 скриптом `scripts/measure_local_model.py` на машине
разработчика: Ryzen 5 5500U, 6 ядер, 15,3 ГБ памяти, без видеоускорителя. Генерация повторялась трижды,
взята медиана: первый прогон дороже из-за загрузки весов в память, и одно измерение дало бы завышенную
оценку.

| Величина | Ориентир был | Факт |
|---|---|---|
| Размер файла весов | около 4–5 ГБ | **4,36 ГБ** |
| Потребление памяти при генерации | около 6–8 ГБ | **4,71 ГБ** |
| Скорость генерации на процессоре | единицы токенов в секунду | **7,9 ток/с** |
| Время до первого токена | секунды | **0,14 с** |
| Первая загрузка весов в память | — | **11,7 с** |

Два расхождения с ориентирами стоит отметить. Память оказалась **меньше** ожидаемой — 4,7 против 6–8 ГБ;
это делает пиковый сценарий раздела 39.2 достижимым на машине с 16 ГБ без ухищрений. Время до первого
токена оказалось **гораздо лучше** ожидаемого — 0,14 с вместо «секунд», но только на прогретой модели:
первая загрузка весов занимает 11,7 с, и в сервисе её нужно выполнять заранее (тот же вывод, что для
импорта LiteLLM в разделе 50.3 контекста).

**Скорость подтвердила главное ограничение.** При 7,9 токена в секунду ответ на 200 токенов занимает
около 25 секунд. Это приемлемо для офлайн-проверок и полностью исключает использование модели для
оценки задержки.

**Скорость важна для одного вывода, который стоит зафиксировать сразу:** локальная модель непригодна для
проверки целевых показателей задержки из критериев готовности (время до первого токена менее 500 мс,
полный ответ менее 3 секунд). Эти показатели проверяются либо на боевом провайдере, либо на конфигурации
тиража. Локальная модель нужна для проверки *логики*, а не *скорости* — при нагрузочных прогонах она даёт
форму нагрузки, но не абсолютные значения задержки (план тестирования, раздел 8).

## 5а. Внешний провайдер прототипа — YandexGPT, а не GigaChat

Решение от 1 сентября 2026. Локальная модель им не заменяется — она остаётся
вторым backend'ом и судьёй; речь о том, кто отвечает абоненту при обращении
наружу.

**Причина одна и техническая.** GigaChat требует корневых сертификатов НУЦ
Минцифры: их нет ни в поставке Python, ни в наборе `certifi`, и без установки
в систему любой вызов падает на проверке TLS. На машине прототипа эти
сертификаты получены не будут. Отключение проверки (`verify=False`) как обходной
путь отвергнуто: по этому соединению идут персональные данные абонента.

**Распределение по контурам:**

| Контур | Генерация | Второй backend | Судья качества |
|---|---|---|---|
| Прототип | YandexGPT | local-test | local-test |
| MVP в проде | GigaChat Pro | YandexGPT | YandexGPT |

Правило ADR-007 «судья не совпадает с отвечающей моделью» соблюдается в обоих
контурах. Требование ADR-002 о двух провайдерах с автопереключением — тоже.

**Цена решения.** Штатной поддержки Яндекса в LiteLLM нет: проверено на версии
1.99.0, в списке из 152 провайдеров есть `gigachat`, но нет `yandex`. Подключение
идёт через OpenAI-совместимый режим с явным адресом, и ответственность за
совпадение формата ответов и потоковой отдачи ложится на нас. Побочный
положительный эффект: более трудный путь интеграции проходится первым, а переход
на MVP означает смену на штатно поддерживаемого провайдера, то есть упрощение.

**Предпосылка проверена — решение в силе.** *(обновлено 1 сентября 2026)*

| Эндпоинт | Доверие стандартным набором | Издатель |
|---|---|---|
| `llm.api.cloud.yandex.net` | **проходит**, TLSv1.3 | GlobalSign nv-sa |
| `gigachat.devices.sberbank.ru` | **не проходит** | `self-signed certificate in certificate chain` |

Измерено дважды скриптом `scripts/check_yandex.py`. Корневые сертификаты НУЦ
Минцифры для Яндекса **не нужны**. Контрольный случай с GigaChat подтвердил и
саму причину замены: без НУЦ его цепочка сертификатов не проверяется.

Ниже — исходная формулировка на момент принятия решения, оставлена как история.

**Непроверенная предпосылка, от которой зависело решение.** Требует ли сам
Yandex Cloud тех же корневых сертификатов, неизвестно — из рабочей сессии сеть
недоступна. Если требует, решение теряет смысл и подлежит пересмотру. Проверяется
одной командой до начала шага 4:

```bash
python -c "import socket,ssl;h='llm.api.cloud.yandex.net';ctx=ssl.create_default_context();s=ctx.wrap_socket(socket.create_connection((h,443),timeout=10),server_hostname=h);print('ДОВЕРЕН, издатель:',dict(x[0] for x in s.getpeercert()['issuer']).get('organizationName'))"
```

Печатает издателя — сертификаты не нужны, решение в силе. Падает с ошибкой
проверки — нужны те же НУЦ, и тогда прототип остаётся на локальной модели без
внешнего провайдера вообще.

## 6. Ограничения, зафиксированные в коде

| Ограничение | Где реализовано |
|---|---|
| Запрещена в production | `LocalTestBackend.ensure_allowed()` — исключение при `APP_ENV=production`, срабатывает до обращения к модели |
| Промпты не логируются | В журнал уходят только имя модели и статистика токенов: тот же кодовый путь используется с внешним провайдером, а логирование сырых персональных данных запрещено правилом 4.2 |
| Понятная диагностика | `preflight()` различает «Ollama не запущена» и «модель не загружена» — иначе оба случая выглядят как невнятная сетевая ошибка |
| Обязателен поток | `stream()` отдаёт фрагменты по мере генерации; живой тест проверяет, что ответ не собирается целиком перед отдачей (правило 4.3) |

## 7. Когда решение пересматривать

- Если тиражная модель перестанет быть Qwen2.5-32B — исчезает главный критерий выбора, и сравнение
  нужно проводить заново.
- Если проверки Security Layer начнут падать из-за того, что модель не удерживает системное сообщение,
  а не из-за реальных дефектов защиты — это признак, что 7B недостаточно для роли.
- Если появится доступ к GPU на машине разработки — можно рассмотреть более крупную модель того же
  семейства, но выигрыш нужно обосновывать: задача модели не изменится.
