# vodokanal-assistant

Прототип AI-помощника абонента водоканала: RAG-ассистент в личном кабинете (Этап 1) с последующим
переходом к агенту с операциями записи через подтверждение абонента (Этап 2).

> **Статус: закрыты код-шаги 0.5, 1–6, 8, 8.5, 9 и часть 10** из четырнадцати по `AI_docs/Dev_Plan.html`;
> шаг 7 закрыт в части оркестрации, без сессий и состояния диалога.
> Полноценный README с установкой и запуском пишется на шаге 11, когда код появится целиком.

## Что уже работает

Шлюз к модели с лимитами, обезличиванием и охранителями; Backend с выбором пути ответа; поиск по базе
знаний; классификация темы; HTTP-интерфейс на двух адресах; демо-стенд; конечный автомат обращения;
адаптеры записи; метрики; доступ к данным Биллинга и личного кабинета.

Сквозной путь проверен на настоящем YandexGPT: страница → API → Backend → шлюз → модель → охранители
→ поток обратно. Два вопроса из четырёх до модели не доходят: об отключении отвечает точный поиск по
графику, а при пустом поиске ассистент отказывается отвечать наугад и называет контакт-центр.

Данные прототипа настоящие, а не выдуманные: FAQ воронежского филиала (20 пар вопрос-ответ), график
плановых отключений (1939 записей по 1821 адресу), выгрузка обращений (136 текстов, персональные
данные замаскированы), пример Биллинга и личного кабинета (200 счетов, 203 счётчика, 1323 начисления).

Качество поиска измерено на эталонном наборе из 66 вопросов (63 настоящих, разметка ручная):
**Recall@3 = 87%**, поиск 33,7 мс при бюджете 100 мс. Тот же замер показал, что порог отсечения
контекста вопросы с ответом и без **не разделяет** — открытый пункт 62 в `AI_docs/TODO.md`.

## Установка и прогон

Тестам не нужны ни Ollama, ни сеть, ни тяжёлый LiteLLM — но нужны те пакеты, которые код
импортирует на уровне модуля:

```bash
python -m pip install --timeout 120 --retries 10 pytest pytest-asyncio ruff mypy pydantic pydantic-settings httpx fastapi sse-starlette prometheus-client pyyaml
```

```bash
python -m pytest -q
```

Ожидаемо: `562 passed, 5 deselected`. Пять отложенных — живые, им нужна модель.

Весь пакет целиком, включая LiteLLM и клиент Redis:

```bash
python -m pip install --timeout 120 --retries 10 .
```

Слой защиты персональных данных ставится отдельно — русская модель spaCy идёт не с PyPI:

```bash
python -m pip install ".[pii]" && python -m spacy download ru_core_news_md
```

Живая проверка на реальной модели — после установки Ollama:

```bash
ollama pull qwen2.5:7b-instruct-q4_K_M && python -m pytest -q -m live
```

Без Ollama живые тесты пропускаются с объяснением, а не падают.

Запуск сервиса и демо-стенда:

```bash
python -m uvicorn app.main:app --reload
```

> `Makefile` дублирует эти команды короткими целями, но `make` в Windows по умолчанию нет —
> основным считается путь через `python -m` выше.

## Скрипты

| Скрипт | Зачем |
|---|---|
| `scripts/fetch_faq.py` | Сборка корпуса базы знаний с сайта филиала; `--check` сверяет сохранённое с сайтом |
| `scripts/sanitize_inquiries.py` | Очистка выгрузки обращений, приведение к одному филиалу, проверка нашим же обезличивателем |
| `scripts/generate_charges.py` | Начисления по счетам примера: услуги, основания, разнесение долга |
| `scripts/normalize_addresses.py` | Приведение адресов примера к воронежским улицам из графика отключений |
| `scripts/build_golden_set.py` | Сборка эталонного набора поиска из разметки и настоящих источников |
| `scripts/measure_retrieval.py` | Замер поиска на эталонном наборе: попадание в тройку и цена порога |
| `scripts/measure_search_models.py` | Замер моделей поиска: вес, память, задержка против бюджета |
| `scripts/measure_classifier.py` | Замер запасного режима классификации на настоящих обращениях |
| `scripts/measure_local_model.py` | Характеристики локальной модели: вес, память, скорость, время до первого токена |
| `scripts/check_yandex.py` | Диагностика подключения к YandexGPT |
| `scripts/build_openapi.py` | Пересборка `AI_docs/API_Spec.yaml` из тех же классов, по которым работает сервис |

## Правила, которые нельзя нарушать

- Персональные данные фильтруются в шлюзе **до** обращения к провайдеру.
- Ответ доходит до абонента потоком.
- Любая операция записи — только после подтверждения абонента, с идемпотентностью и аудитом.
- У каждой оси классификации один справочник и одно назначение; значения разных осей никогда не
  сравниваются между собой (ADR-011).
- Что проверяется по факту, отвечается точным поиском, а не генерацией по найденному
  (ADR-012, ADR-013).
- Зарубежные провайдеры общего назначения в конфигурацию шлюза не добавляются (152-ФЗ).
